# Object21 GNN 입력의 좌표 오차와 꼭짓점 누락 분리 평가

## 실험 설정

[이동 Box GT 학습](moving_box_gt20_training.md)의 고정·이동 혼합 GNN 체크포인트를 동결했다. [강체 보정 연결 실험](rigid_box_object21_eval.md)과 같은 새 Main 카메라, 이동 Box 테스트 시드 32개(3100144–3100175) 및 3,352프레임을 사용했다. Box가 실제로 움직인 695프레임과, 각 장면에서 물체를 잡은 뒤 마지막 정렬 5프레임으로 구성한 삽입 직전 160프레임을 주요 비교 구간으로 삼았다. 행동은 기존 Expert 궤적을 따랐다.

원본 입력은 시뮬레이터의 Peg 꼭짓점 8개, Box 외곽 꼭짓점 8개, 앞쪽 Hole 입구 꼭짓점 4개와 TCP다. 다음 조건에서 같은 그래프 생성 코드와 가중치를 사용했다.

- **원본 GT**는 20개 좌표 모두 정확하고 관측 플래그도 모두 켜져 있다.
- **좌표만 교란**은 매 프레임의 각 점을 독립적으로 선택한 무작위 3D 방향으로 일정 거리만큼 이동한다. 모든 비교에서 같은 방향 표본을 사용하고 거리만 1·3·5·10·20·40 mm로 변경했다. 20개 점과 관측 플래그를 유지했다.
- **점만 제거**는 GT 좌표 그대로 남기되 프레임별로 실제 가시 GT 점, 실제 검출과 대응한 점, 현재 검출 또는 과거에 신원이 확인된 추적점만 남기는 세 조건을 사용했다. 누락만 분리하기 위해 남은 점의 관측 플래그를 켰다. 누락에 취약한 점 집합을 찾기 위해 Peg, Box 외곽, Hole 입구의 한 그룹에만 추적 대응 마스크를 적용하는 조건도 평가했다.
- **실제 좌표 오차 적용**은 현재 검출 또는 과거 관측을 통해 GT 신원을 연결할 수 있는 점에만 추정 좌표의 오차 벡터를 적용했다. 20개를 유지하는 조건에서는 대응이 없는 자리에 정확한 GT를 남겼다. 동일한 오차 벡터로 점 누락을 추가하고, 실제 관측 플래그를 추가하는 조건도 순서대로 비교했다. 기존 Transformer 좌표와 [강체 보정](rigid_box_tracking_eval.md) 좌표 각각에 대해 계산했다.

실제 검출점의 신원은 동일 물체의 가시 GT 꼭짓점과 5 mm 범위에서 일대일 슬롯으로 매칭했다. 현재 검출이 끊긴 추적점에는 가장 최근에 확인한 신원을 적용했으며 같은 꼭짓점에 여러 후보가 있으면 현재 검출, 이후 가장 최근에 매칭된 추적점 순으로 선택했다. 이 방식은 평가용으로만 사용했다. 모든 후보를 전달했던 실제 파이프라인과 달리, GT에 대응되지 않은 점·후면 Hole 점·중복 track은 대응 조건에서 제외된다.

## 결과

횡방향 오차는 예측한 Peg 끝점–Hole 중심 벡터의 오차를 GT 삽입축에 수직인 평면에 투영한 크기다. P90은 해당 구간 전체 프레임 오차의 90번째 백분위수다.

### 좌표 교란과 누락 비교

| 입력 조건 | Box 이동 중 횡방향 P90 (mm) | 삽입 직전 횡방향 P90 (mm) |
| --- | ---: | ---: |
| 원본 GT 20점 | 2.86 | 2.67 |
| 20점 유지, 각 점을 1 mm 이동 | 3.28 | 3.41 |
| 20점 유지, 각 점을 3 mm 이동 | 5.32 | 5.20 |
| 20점 유지, 각 점을 5 mm 이동 | 7.92 | 7.64 |
| 20점 유지, 각 점을 10 mm 이동 | 15.08 | 14.08 |
| 20점 유지, 각 점을 20 mm 이동 | 28.95 | 27.68 |
| 20점 유지, 각 점을 40 mm 이동 | 56.87 | 53.22 |
| 20점 유지, GT와 대응한 점에 기존 Transformer의 오차 적용 | 16.35 | 25.16 |
| 20점 유지, GT와 대응한 점에 강체 보정 후 좌표 오차 적용 | 9.45 | 8.22 |
| 정확한 좌표 유지, 가시 GT 점만 남김 | 83.65 | 96.68 |
| 정확한 좌표 유지, 현재 검출과 대응하는 점만 남김 | 105.22 | 98.53 |
| 정확한 좌표 유지, 검출·추적에서 신원 확인된 점만 남김 | 65.97 | 60.83 |
| 강체 보정 좌표 오차와 검출·추적 누락 적용 | 70.35 | 62.83 |
| 강체 보정 좌표 오차, 검출·추적 누락, 관측 플래그 적용 | 70.44 | 64.01 |
| 기존 평가의 전체 검출·추적 입력 + 강체 보정 | 58.94 | 63.60 |

강체 보정 후 GT와 대응한 2,611개 점의 좌표 오차 P90은 삽입 직전 3.16 mm였다. 같은 프레임에서 검출·추적으로 신원이 확인된 점은 평균 16.32개였다. 남은 좌표를 모두 정확한 GT로 바꾸고 누락만 적용해도 횡방향 P90이 60.83 mm였고, 이때 중앙값은 39.70 mm였다. 강체 보정 후 측정된 좌표 오차를 20점 유지 상태에서 적용하면 P90은 8.22 mm, 중앙값은 2.51 mm였다. 이번에 분리한 조건에서는 좌표 오차보다 점 누락의 영향이 더 컸다.

20점을 유지한 경우 GT와 대응할 수 없었던 점은 정확한 좌표로 채웠으므로, 8.22 mm는 신원이 확인된 점의 오차에 대한 민감도다. 오검출과 대응 실패 전체의 영향은 이 값으로 추정할 수 없다. 누락·좌표 오차·관측 플래그를 모두 적용한 경우 횡방향 P90은 기존 실제 입력 결과와 비슷했으나 삽입축 P90은 17.71°로 전체 검출·추적 입력에서 얻은 37.49°와 달랐다. 이 진단은 실제 입력을 통째로 재현하지 않는다.

실제 GNN 입력의 track 수와 GT 꼭짓점에 대응시킨 수는 별개다. 추적기는 새 검출과 대응하지 않은 기존 track도 예측해 전달하며, 기존 track과 대응하지 않은 검출에는 새 track을 만든다. Peg·Box 외곽·Hole 입구의 물리 꼭짓점 수에 맞춰 track을 선택하지 않는다. 삽입 직전 160프레임의 실제 GNN 입력은 20–39개(평균 28.92개)였고, 그중 155프레임은 20개를 초과했다. 같은 프레임에서 GT 신원이 확인된 점은 14–18개(평균 16.32개)였다. 누락 실험은 신원이 확인되지 않은 GT 슬롯을 제거했을 때의 민감도를 측정한다. 정확한 대응을 확인하지 못한 슬롯에도 실제 입력에서 근처를 추정한 예측점이 있었을 수 있다.

### 점 그룹별 누락

각 행에서 해당 그룹만 실제 검출·추적 대응 패턴만큼 누락시켰다. 다른 두 그룹의 점은 정확한 좌표로 모두 유지했다.

| 누락을 적용한 그룹 | 삽입 직전 남은 점 평균 | 이동 중 횡방향 P90 (mm) | 삽입 직전 횡방향 P90 (mm) | 삽입 직전 Hole 중심 P90 (mm) |
| --- | ---: | ---: | ---: | ---: |
| Peg | 6.68 / 8 | 38.99 | 11.11 | 2.87 |
| Box 외곽 | 5.77 / 8 | 70.17 | 64.12 | 78.80 |
| Hole 입구 | 3.87 / 4 | 3.19 | 7.42 | 11.24 |

이번 누락 패턴에서는 Box 외곽점만 제거해도 삽입 직전 횡방향 P90이 64.12 mm로 커졌다. 이 조건에서는 Hole 입구 네 점도 정확하게 주어졌다. 고정 20점으로 학습한 모델의 Box 외곽 누락 민감도를 보여준다. 각 그룹의 실제 누락률과 누락된 위치가 다르고, 특히 Hole 입구는 대부분 추적에서 대응됐으므로 그룹별 점 한 개의 중요도를 직접 비교할 수는 없다. 오차 백분위수는 그룹 사이에서 더하거나 빼서 기여도를 계산할 수 없다.

## 검증과 범위

Vast.ai RTX 3090에서 CPU PhysX와 CUDA 렌더링·검출·추적을 수행해 입력을 수집했고, 저장된 프레임에서 CUDA로 같은 체크포인트의 GNN 추론을 수행했다. 모든 실행은 공통 ExperimentLogger로 기록했다. 이전 재생과 3,352프레임의 시드·스텝, 세 그룹의 가시·검출 매칭 점수, 강체 이동량을 확인했다. 원본 GT 입력으로 기존 Object21 예측을 재현했고, 저장된 예측으로 이동 중·삽입 직전의 횡방향 중앙값과 P90을 NumPy에서 독립 계산해 확인했다. 공통 코드나 가중치 변경은 없었다. Recurrent와 실제 삽입 성공률은 평가하지 않았다.
