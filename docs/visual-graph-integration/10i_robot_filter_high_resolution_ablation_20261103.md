# Task 10-I: 고해상도 실제 마스크의 로봇 필터 비교

2026-11-03 KST. 사용자 요청에 따라 기존 기록과 저장된 실제 마스크를 이용한 **선택 사례 진단**이다. 공통 simulator·기존 Graph·원래 정지된 Task 10-I 실험은 수정하거나 재개하지 않았다. SAM2 등 모델 추론, API 호출, 학습, rollout, 패키지 설치, 게시를 하지 않았다.

## 결론

이번 선택 사례에서 로봇 필터를 완전히 끄면 Graph 생성은 상당히 빨라지고 손가락 근처 정상 마스크 픽셀도 더 남았다. 그러나 1024 입력 26개 중 **25개 시점에서 최종 Graph의 로봇 대표점 수가 증가**했고, 그 25개에서 정상 물체 대표점 수는 감소했다. 26개를 합친 로봇 대표점은 현재 필터 **49/6,656개**, 확실한 로봇만 제거 **62/6,656개**, 필터 끔 **191/6,656개**였다. 세 집계는 같은 26개 조건의 서로 다른 출력을 비교한 것이며 모집단 오염률은 아니다.

확실한 로봇만 제거하면 불확실 band에서 지워졌던 정상 픽셀을 일부 보존했다. 다만 이 후보에서도 로봇 점이 증가한 시점이 있었고, 현재 비교 구현은 여전히 전체 로봇 필터를 계산하므로 속도상 대체 경로라고 할 수 없다. **이 결과만으로 필터 제거 또는 완화의 실용 채택을 권고하지 않는다.** 같은 판정을 물체 마스크 영역에만 계산하는 의미 보존 최적화는 이번에 구현·측정하지 않았다.

## 사례 선택과 데이터 경계

처음 검토한 8개 시점은 입력 가용성 확인용이며 본 표본이 아니다. 사용자의 후속 요청을 반영해 [기존 Stage4A 128 필터 프레임 감사](../../outputs/task10i/stage4a/final_evidence_58576054/completion/filters/robot_filter_frame_metrics.json)와 저장된 512 실제 입력의 기존 필터 결과를 대조했다. **512 결과와 과거 기록만으로** 다음 기준과 deterministic 부모별 선정을 먼저 고정했다.

- **실패군:** 관련 카메라/물체에서 정상 마스크 픽셀의 16개 이상 및 1% 이상을 필터가 제거했거나, 원래 로봇 픽셀이 64개 이상인데 64개 이상·20% 이상이 남은 사례. 과거 정확히 같은 Parent/시점의 finger-near 기준 픽셀 5개 이상 중 10% 이상이 제거된 기록도 포함한다. 성공 조건과 겹치면 실패군으로 분류한다.
- **성공군:** 실패 기준에 해당하지 않으면서, 어느 관련 입력 마스크의 로봇 픽셀 128개 이상 중 90% 이상을 제거하고 정상 픽셀 손실이 `max(16개, 정상 픽셀의 1%)` 이하인 사례. 이는 **로봇 제거 측면의 성공**이며 전체 인식·Graph·정책 성공을 뜻하지 않는다.
- **일반군:** 나머지 감사 성공 사례. 주로 원래 로봇 혼입이 적은 조건이다. 어떤 후속 지표가 정상이라는 보증은 아니다.

Relevant 조건은 Main Peg/Box와 Wrist Peg다. Wrist Box는 기존 Graph 정책상 사용하지 않으므로 사례 선정에서 제외했다. 115개 512 시점 감사가 모두 완료됐고, 위 조건에 해당하는 실패 4개·성공 7개를 모두 선택했다. 일반 104개 중 Parent를 우선 분산하는 고정 SHA 순서로 15개를 선택했다. 부류 안의 각 선택 사례는 서로 다른 Parent다. 부류 간에는 같은 Parent의 서로 다른 시점이 포함된다.

| 선택군 | 시점 수 | 군 내 Parent 수 | 768·1024 조건 수 |
|---|---:|---:|---:|
| 실패 | 4 | 4 | 8 |
| 성공 | 7 | 7 | 14 |
| 일반 | 15 | 15 | 30 |
| 전체 | **26** | **18** (군 간 중복 있음) | **52** |

예를 들어 `10i_s1_0924_t080`은 과거 128 감사에서 Main의 finger-near GT Peg 18개 중 4개를 잘못 제거한 기록이 있다. 같은 물리 시점의 512 실제 마스크 감사에서도 Main Peg 정상 5,969개 중 64개가 제거됐다. 과거에 보고된 `0355/t66,t85` 등 일부 중요한 사례에는 동일 시점의 동결된 native 768/1024 실제 마스크가 없어 이번 비교에 포함하지 않았다. **없는 고해상도 사례를 재생성하거나 기존 실험을 재개하지 않았다.**

512와 768/1024는 같은 물리 시점이지만 각각의 native 입력에서 저장된 서로 다른 실제 마스크다. 따라서 512에서의 사례군이 고해상도에서도 같은 특성을 보장하지 않는다. 512 GT를 사례 선택에 사용했고 동일한 물리 장면을 더 높은 해상도에서 평가했으므로 독립적인 새 장면의 holdout 평가가 아니다. 의도적으로 어려운 사례를 선택한 만큼 전체 데이터의 실패율·일반화·통계적 우월성으로 해석하지 않는다. 특히 실패군은 **4 Parent**뿐이다.

예외적으로 최종 비교 실행 전 계측 코드 점검을 위해 `0924/t080`, `0686/t000`의 1024 입력 두 건에 대해 세 방식의 smoke 출력을 먼저 동결하고 GT 채점을 실행했다. 이때 출력 일관성과 채점 성공 상태만 확인했고 정량 결과에 따라 사례·정책·임계값을 바꾸지 않았다. 이후 본 비교의 52개 조건 출력을 다시 모두 동결한 뒤 최종 GT 채점을 수행했다. Smoke도 같은 장면을 사용한 만큼 독립 평가 증거로 취급하지 않는다.

## 비교 방식

동일 시점·동일 해상도·동일 저장 actual mask repeat 0을 사용한다. 공통 Graph 후보는 이전 독립 최적화의 Stage 9다. 세 방식은 로봇 필터 정책만 다르다.

| 방식 | 필터에서 제거하는 것 |
|---|---|
| 현재 `full` | confirmed robot, uncertain robot, 두 물체 마스크 overlap |
| `confirmed_only` | confirmed robot, overlap. uncertain은 보존 |
| `off` | 로봇 필터 계산 생략. 물체 간 overlap 제거는 유지 |

세 조건 모두 Wrist gate, 두 카메라 융합, Shape-First, 원본 source 보존, 3mm 중복 제거, 물체별 cap128, Graph21/Edge4와 검증을 유지한다. 단, 입력 마스크가 달라질 수 있으므로 선택점과 엣지가 달라지는 것은 이 **정책 ablation의 측정 대상**이다.

512의 Actor GT는 사례군 선정에만 사용하고 Graph의 입력으로 전달하지 않았다. 본 실험의 768/1024 Graph·mask·source·gate·시간·SHA receipt를 모두 동결한 뒤 해당 해상도의 저장 Actor segmentation을 열어 점수를 계산했다. 추정·채점에서 추가 GT 보정은 없다.

## 시간: CPU 입력 → CPU 최종 Graph

RTX 3090 24 GiB, AMD EPYC 7543, PyTorch 2.14.1+cu130, Triton 3.8.0. CPU affinity 128 logical CPU, 컨테이너 CPU quota 약 6.47 CPU, Torch intra-op 4, OMP/OpenBLAS/MKL 각각 1이다. 각 조건·방식별 워밍업 1회 후 3회 측정하고, 동일 사례에서 방식 순서를 바꿨다. 표의 값은 **각 사례의 3회 중앙값을 구한 후, 해당 군 사례들의 중앙값**이다.

경계는 CPU 센서 배열·마스크·사전 계산된 로봇 형상 입력부터 CPU Graph·records·gate 반환까지다. 내부 CPU↔GPU 전송을 포함한다. 파일 읽기/압축 해제, 입력 join, 별도 FK, SAM2, action 추론, GT 채점은 포함하지 않는다. 세 번과 선택된 사례만으로 p95, 최악 지연, 센서→action 50ms 달성을 주장할 수 없다.

1024 전체 26개에서 사례별 중앙값의 중앙값은 `full` 427.4ms, `confirmed_only` 420.8ms, `off` 279.9ms였다. 같은 사례의 `off−full` 시간 차이 중앙값은 **−139.9ms**다. 768의 대응 차이 중앙값은 **−87.1ms**다. 개별 조건의 선택점·gate 이후 작업량도 바뀔 수 있으므로 이 차이를 순수 필터 커널 시간으로 취급하지 않는다. `confirmed_only`는 현재 코드에서 confirmed와 uncertain을 둘 다 계산하고 나중에 uncertain만 보존하므로, 별도 경량 구현의 속도는 미측정이다.

각 프로세스 data 한도는 80 GiB다. 전체 사례 중 측정 프로세스 RSS high-water 최댓값은 full/confirmed/off 각각 약 **1.651/1.650/1.643 GiB**, PyTorch 최고 allocated는 **116.2/116.2/100.2 MiB**였다. RSS에는 Python·의존성·입력 등이 포함되고, PyTorch allocated는 CUDA 컨텍스트 전체·다른 프로세스의 GPU 점유량이 아니다.

## 정확도: 픽셀과 Graph 대표점을 구분

아래 로봇 수는 최종 Graph의 Peg·Box **대표점 첫 출처**를 Actor GT로 분류한 것이다. 중복 병합된 모든 출처의 수와는 다르다. 손가락 근처는 기록된 양쪽 finger-pad centre 중 하나에서 20mm 미만인 관측점이며 contact-force GT가 아니다. 손가락 근처 보존율은 **원래 해당 SAM2 마스크 안에 있고 GT상 정상이며 유효 깊이를 가진 픽셀**이 clean mask에 남은 비율이다. 마스크에 처음부터 없던 GT 픽셀은 분모에 넣지 않았다. Overlap도 세 방식 모두 제거하므로 off가 항상 100%는 아니다.

| 해상도 | 방식 | Robot 대표점 / 전체 대표점 | 로봇 대표점이 1개 이상인 사례 | 손가락 근처 정상 픽셀 보존 |
|---|---|---:|---:|---:|
| 768 | full | 32 / 6,656 | 12 / 26 | 2,372 / 2,896 = 81.9% |
| 768 | confirmed-only | 43 / 6,656 | 13 / 26 | 2,621 / 2,896 = 90.5% |
| 768 | off | 185 / 6,656 | 23 / 26 | 2,896 / 2,896 = 100.0% |
| 1024 | full | 49 / 6,656 | 15 / 26 | 4,385 / 5,381 = 81.5% |
| 1024 | confirmed-only | 62 / 6,656 | 15 / 26 | 4,849 / 5,381 = 90.1% |
| 1024 | off | 191 / 6,656 | 25 / 26 | 5,376 / 5,381 = 99.9% |

1024에서 병합된 모든 observation source 중 로봇 출처는 full **71/16,587**, confirmed-only **96/16,535**, off **451/16,827**이다. 대표점과 attached source는 별도 분모다. 정상 대표점 수는 각각 **6,127**, **6,114**, **5,986**이었다. 그리퍼 근처 정상 대표점 수는 각각 **44**, **46**, **35**였다. 따라서 더 많은 정상 픽셀을 남겼다는 사실이 cap128 이후 정상 대표점 증가를 보장하지 않는다.

동일 사례 paired 비교에서 1024 `off`는 full보다 로봇 대표점이 **25/26 사례에서 증가**, 정상 대표점이 **25/26 사례에서 감소**했다. `confirmed_only`는 각각 5/26 사례였다. 768 `off`는 각각 23/26 사례였다. Wrist gate의 accepted/rejected 결과는 세 방식 사이에서 768·1024 모두 변하지 않았다. Graph의 선택 source는 1024에서 off 25/26, confirmed-only 7/26 사례가 달라졌다.

## 실패·성공·일반 사례 비교

표의 Peg coverage는 올바른 source의 최종 대표점에서 4mm 이내인 **같은 해상도 GT 유효 깊이 관측점의 비율**을 사례별로 계산해 평균한 값이다. Peg는 두 카메라, Box는 Main을 reference에 사용한다. 카메라 픽셀 밀도와 중복에 가중되며 물리적인 전체 표면적이나 숨은 표면 복원을 보장하지 않는다.

| 1024 사례군 | 방식 | Robot 대표점 / 전체 | 손가락 근처 정상 픽셀 보존 | Peg visible coverage 평균 |
|---|---|---:|---:|---:|
| 성공 7 | full / confirmed / off | 18 / 23 / 64 중 각 1,792 | 1,310 / 1,457 / 1,614 중 각 1,614 | 44.0 / 43.0 / 41.3% |
| 실패 4 | full / confirmed / off | 23 / 31 / 75 중 각 1,024 | 2,981 / 3,296 / 3,661 중 각 3,661 | 38.2 / 37.4 / 34.9% |
| 일반 15 | full / confirmed / off | 8 / 8 / 52 중 각 3,840 | 94 / 96 / 101 중 각 106 | 35.7 / 35.7 / 35.6% |

**실패 사례 `0044/t080`, 1024:** Main Peg의 원래 mask에는 정상 9,145픽셀과 Robot 1,540픽셀이 있었다. 손가락 근처 정상 픽셀은 원래 479개였고, full/confirmed/off clean에서 각각 **365/429/479개**가 남았다. 그러나 최종 Peg 대표점의 로봇 수는 **6/6/22개**, 정상 수는 **116/116/99개**, 손가락 근처 정상 대표점은 **10/8/5개**였다. Peg visible coverage는 **42.22/42.65/38.92%**였다. 이 한 사례는 off에서 정상 near-mask가 늘어도 로봇 점과의 최종 예산 경쟁을 포함한 후단 선택 결과가 나빠질 수 있음을 보여 준다. 오직 예산 경쟁 하나만의 독립 인과 실험은 아니다.

**성공 사례 `0193/t080`, 1024:** Main Peg 마스크에는 정상 1,338픽셀과 Robot 541픽셀이 있었다. full은 Robot을 1픽셀로 줄였고, off는 541픽셀을 남겼다. 최종 Peg의 Robot 대표점은 **1→10개**, 정상 대표점은 **116→107개**, Peg visible coverage는 **69.18→57.59%**였다. 이 사례에서 필터 제거는 유의미한 표면 품질 손실과 동반됐다.

**일반 사례 `0720/t080`, 1024:** 512 기준 일반군이었지만 1024 Main의 원래 마스크에는 Peg slot Robot 46픽셀과 Box slot Robot 90픽셀이 있었다. full에서 두 물체를 합친 Robot 대표점은 4개, off에서는 14개였다. 따라서 512에서 깨끗한 마스크가 다른 native 해상도에서도 같은 오염 수준을 갖는다고 가정하면 안 된다.
