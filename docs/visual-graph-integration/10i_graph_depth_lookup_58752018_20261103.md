# Task 10-I — Graph free-space의 전체 depth 재생성 제거

2026-11-03. 전체 depth getter 접근 대신 **투영된 raw depth pixel만 조회·변환**하도록
수정했다. 같은512 입력과 기존 Graph endpoint에서 EE 중앙값이
**792.852ms →167.997ms**, 약4.72배로 줄었다. World는768.462ms →149.931ms다.
Graph1회당 전체 depth getter 호출은 **1,964회 →0회**다.

## 변경

[graph.py](../../graph/persistent_geometry/graph.py)의 `free_space_violation`만 수정했다.

- Image shape은 `camera.depth_raw_mm.shape`에서 직접 읽는다.
- 기존과 같은 projection/floor/bounds 검사를 한 뒤, 필요한 `(v,u)`의 raw int16만 gather한다.
- 선택된 raw 값에 기존과 같은 **float64 `/1000`**, `raw<=0 →NaN` 규칙을 적용한다.
- 이후 `isfinite`와 strict **`p_z < depth_m -0.006`** 판단은 그대로다.

한 엣지 pair의 witness는3점이므로 한 camera에서 필요한 depth는 최대3개다.
전체 배열을 frame마다 한 번 cache하는 방법보다 작업 범위를 더 줄여, 전체 float64
depth 배열 생성 자체를 없앴다. 전역/frame cache를 만들지 않아 원본 depth·calibration·
pose가 갱신되면 다음 호출에서 바로 반영한다.

Projection, camera/EE/World 좌표계, invalid/overflow 처리, normal/tangency/witness,
free-space threshold, 엣지 선택·순서·attributes·Graph 구성 규칙은 변경하지 않았다.
`CameraObservation.depth` getter 자체는 수정하지 않아 로봇 필터/gate 등 다른
소비자의 동작은 그대로다. Graph는 여전히 **CPU**에서 계산·반환한다.

## 측정 경계·조건

직전 [기준 측정](10i_graph_build_timing_58752018_20261103.md)과 같은 endpoint다.
준비된 **CPU post-FPS 기록128개 + robot geometry/calibration/raw depth**에서 시작해
`PlanA.graph`와 `CurrentGeometry._finish`의 최종 반환까지 측정했다.
GPU→CPU 반환, 앞선 point 처리/FPS, robot FK/filter/gate, model packing/upload/inference는 제외한다.

VastAI **58752018**, RTX3090/AMD EPYC7543의 기존 환경,
NumPy2.5.4, Torch2.14.1+cu130. OMP/BLAS/MKL/Torch threads1,
CPU affinity·공유 host 부하 고정 없이 기본 Python GC를 유지했다.

동일 실제 `10i_s1_0844_t080` hand512×512 입력이다. **Peg128, Box0**,
131nodes/1,006edges다. Base는 hand depth/calibration을 복제한 빈 관측으로,
두 camera 객체 모두 depth 검사에 참여한다. 독립된 두 실제 sensor나 nonempty Box의
성능을 측정한 것은 아니다.

이전 입력 파일의 SHA256과 이번 입력이 정확히 같음을 검사했다. 상류 실제 GPU
pipeline에서 준비한 기록이 공개 `CurrentGeometry.build`의 기록과 일치하는지 확인했다.
실제 FK를 사용하되, `robot_filter_backend='cpu'`와 준비된 조건으로 `system.prepare`를
대체해 별도 작업인 로봇 필터/gate를 실행하지 않았다.

## 전체 시간

각 frame20회 warmup 후100회, EE/World 실행 순서를 매번 교대했다.
Primary timer에는 내부 진단 hook이 없으며 CPU wall `perf_counter`로 측정했다.
GPU 작업은 시작 전에 끝냈고 timer 안에는 CUDA 호출이 없다. 이전 출력 해제,
진행 로그, Logger/file IO는 다음 timer 밖이다.

수정 전은 직전 완료된100회 기준 측정을 재사용했다. **새로 교대 실행한 paired 전후
측정이 아니라**, 동일 입력·endpoint·환경의 별도 실행 비교다. 기준 결과는 덮어쓰지 않았다.

| 좌표계 | 수정 전 중앙값 | 수정 후 중앙값 | 수정 후 p95 | 중앙값 비율 |
| --- | ---: | ---: | ---: | ---: |
| **EE, 기본** | **792.851780ms** | **167.997037ms** | **178.484294ms** | **4.72배** |
| World | 768.462232ms | 149.930768ms | 157.155315ms | 5.13배 |

수정 후 최소/최대는 EE153.454269/190.363608ms,
World133.975674/168.634773ms다. Raw 표본은 제거하거나 보정하지 않았다.
CPU의 불필요한 전체 이미지 작업을 제거한 결과이며 GPU Graph 이식의 결과는 아니다.

## 별도 내부 진단

각 frame5회 warmup·20회 별도 진단으로 같은 원래 호출을 감싸 계측했다.
모든 표본에서 free-space 검사491회는 그대로이고 전체 depth getter는0회였다.
Getter를 예외로 막은 Graph 실행도 통과했다.

| 진단 구간 | 수정 후 EE 중앙값 | 수정 후 World 중앙값 |
| --- | ---: | ---: |
| 전체 depth getter 합계 | **0ms** | **0ms** |
| 노드/특징 준비 | 1.407550ms | 1.345421ms |
| free-space 검사 합계 | 138.677111ms | 119.448190ms |
| 표면 내부 엣지, 위 검사 포함 | 169.949603ms | 150.934979ms |
| 로봇–물체 nearest pairs | 0.164815ms | 0.162440ms |
| Peg–Box pairs, Box0 early return | 0.010000ms | 0.009930ms |
| Edge attributes | 0.101820ms | 0.102725ms |
| 기타 Graph 배열·metadata·tensor 구성 | 0.074600ms | 0.072185ms |
| PlanA schema/status 검사 | 0.044945ms | 0.045440ms |
| 최종 검사 | 0.202290ms | 0.201445ms |

0ms는 **전체 이미지 getter**가 호출되지 않았다는 뜻이다. 소수 pixel의 mm→m 변환
시간은 free-space 검사 안에 포함된다. 진단은 별도 실행·계측 오버헤드를 포함하며,
surface/free-space는 부모·자식 구간이므로 합산하지 않는다. 구간별 중앙값 합계도
기본 전체 시간의 정확한 시간 예산은 아니다.

이번 수정 뒤에도 free-space의 나머지 좌표 변환·투영·검사와 Python 표면 엣지 처리는
남아 있다. 이들의 최적화나 GPU 이식은 이번에 수행하지 않았다.

## 정확성·테스트

- 로컬77개 테스트 중69개 통과·8개 CUDA skip. Vast에서는 **77개 모두 통과**했고
  기존 CUDA entrypoint 관련 검사도 실제 실행했다. macOS CUDA는 실행하지 않았다.
- Signed int16 **65,536개 값**을 기존 dense getter로 계산한 free-space 판정과 비교했다.
  Float64 변환,0/음수/-32768, strict6mm와 양쪽 nextafter, outside/behind/empty를 검사했다.
- Depth in-place 변경·새 배열 교체·camera pose 변경 시 stale cache가 없는지 검사했다.
- 비항등 TCP pose의 World/EE, 여러 camera와 invalid depth, 표면 edge accept/reject와
  audit/order, getter 접근 금지 조건도 검사했다.
- 실제512 표본의 수정 전 frozen Graph tensor/packet과 수정 후를 직접 비교했다.
  **다섯 Graph tensor의 dtype/value/순서, packet·audit가 모두 정확히 일치**했다.
- 두 frame 모두131nodes/1,006edges: 표면982, 로봇–물체24, Peg–Box0.
  Audit는 후보584/normal 제외40/witness 제외53/free-space 제외0으로 동일하다.
- Public `CurrentGeometry.build`의 기록과 입력 불변성도 확인했다.
