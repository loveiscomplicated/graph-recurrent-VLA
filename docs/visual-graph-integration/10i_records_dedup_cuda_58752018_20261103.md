# Task 10-I — 점별 기록 구성·3mm 중복 제거를 GPU로 전환

2026-11-03. 기본 triton_fused SF 경로에서 view 검사 이후의 기록 구성과
3mm 중복 제거를 GPU로 옮겼다. 이 구간은 **GPU 입력 → GPU 출력**이며,
512 입력의 paired 측정에서 EE 중앙값 **CPU30.566ms → GPU4.054ms**,
약7.54배로 단축됐다. 다음 CPU 소비자용 변환까지 포함하면5.931ms다.

## 실제 연결과 범위

현재 기본 `CurrentGeometry(perception_backend='triton_fused')` 경로:

```text
GPU mask projection / triton_fused / Shape-First
  → GPU packet / same-frame observations / view check
  → current_records_tensor
  → deduplicate_tensor(.003)
  → TensorRecords on GPU                         이번 단계의 출력
  → numpy_records                               다음 CPU 소비자용 명시적 경계
  → 기존 최종128점 FPS / Graph 생성             이번 작업에서 이식하지 않음
```

기존 `numpy_observations`는 기본 SF 경로에서 더 이상 호출하지 않는다.
점마다 Python dict를 만든 뒤 중복을 제거하던 순서를, **GPU 열 단위 기록 →
GPU 중복 제거 → 필요한 CPU 소비자에서 대표점 dict 생성**으로 바꿨다.
기본 Graph는 `PlanA.represent(..., ('SF',), tensor_records=True)`를 사용해
GPU 결과를 받은 다음, 최종 FPS 직전에만 호환 변환을 호출한다.
새 metadata `records_dedup_backend='torch_cuda'`로 실제 경로를 확인할 수 있다.

로봇 필터와 sampling 전 wrist gate는 변경하지 않았다. CPU perception은 기존
CPU 경로를 유지한다. 다른 작업의 선택적 `cuda_resident` prototype, native CPU
consumer, SAM2/입력 전송 구현도 수정하지 않았다. SF-only GPU 반환은 사용하지 않는
L/H 진단 분기를 계산하지 않으며, 이 비용은 기존·새 단계 시간 양쪽 모두 제외한다.
학습·평가·정책 성공률은 이 작업에서 측정하지 않았다.

## GPU 기록과 동일한 대표점 규칙

`current_records_tensor`는 같은 episode/time/frame/EE reference의 이미 검증된
tensor 관측을 받는다. XYZ/normal/F5는 float64, source/object/camera ID는 int64,
validity/structural은 bool이며 모두 입력 device에 남긴다. Identity 문자열과
camera 이름은 작은 공통 metadata로 보관하고, 점별 ID는 camera/pixel tensor로
표현한다. 선택한 World/EE 좌표를 다시 변환하지 않는다.

`deduplicate_tensor`는 다음 규칙을 유지한다.

1. `(object_id, not structural, episode, time, camera, numeric pixel)`로 stable
   정렬한다. Episode/time은 공통 metadata이며 pixel을 문자열로 정렬하지 않는다.
2. 가장 앞의 미배정 점을 실제 representative로 선택한다. 같은 물체의 아직
   미배정인 점 중 3mm cell이 인접하고 Euclidean 거리 **`<0.003m`**인 점만
   그 representative에 배정한다. 그다음 가장 앞의 미배정 점으로 진행한다.
3. 이 순서는 기존의 “현재 점에서 먼저 유지된 대표점 중 가장 앞의 hit를 선택”과
   동등하다. A–B, B–C가 가까워도 A–C가 멀면 전체를 합치는 connected-components
   방식이 아니다. 여러 representative와 가까우면 가장 먼저 유지된 것을 따른다.
4. XYZ/F5/normal/validity는 선택한 실제 관측에서 gather한다. 평균하지 않는다.
   Structural 우선 정렬로 각 병합 그룹의 structural 의미도 유지한다.
5. GPU stable sort/gather로 그룹 내 원래 순서의 모든 source ID를 보존한다.
   `source_offsets`, `source_camera`, `source_pixels`가 ragged 출처 목록을 표현한다.

Torch가 정렬·구성·gather를, Triton이 cell과 ordered greedy 반복을 처리한다.
Cell은 float64 round-to-nearest division 후 floor, 거리는 float64 곱·합·sqrt이며
FP contraction을 끈다. 기본 buffer는 O(N)이고, N×N 거리 행렬을 만들지 않는다.
Kernel 내부에서 representative 반복을 수행하므로 점마다 Python이 GPU 종료를
확인하지 않는다. Chunk 처리는2,048점을 넘는 입력에서도 검증했다.

입력의 유한값/지원 가능한 int64 grid 범위를 한 번 모아 검사하고, dynamic
대표점 compaction을 수행하므로 scalar/shape 동기화는 남는다. Zero-sync 또는
순수 kernel 시간이라고 주장하지 않는다. CUDA에서 CPU 수치 연산 fallback은 없다.
명시적 CPU Torch device도 같은 API를 지원한다.

`numpy_records`는 명시적 packed readback 후 기존 `current_records`를 재사용해
대표점의 Python 계약을 복원한다. 이 입력에서는 representative212개의 상세 배열과
모든1,105개 source의 정수 provenance를 내려받는다. Source provenance가 모두
212개로 줄어드는 것은 아니다. `PlanA.represent`의 기존 호출 형식을 유지해야 하면
`tensor_records=False` 기본값이 이 호환 변환을 GPU dedup 뒤에 호출한다.

## 측정 조건과 endpoint

VastAI **58752018**, AMD EPYC7543, RTX3090, 기존 환경에서 실행했다.
Python3.12.15, Torch2.14.1+cu130, NumPy2.5.4. OMP/BLAS/MKL/Torch threads1.
CPU affinity·공유 host 부하는 고정하지 않았고 Python GC는 기본 설정을 유지했다.

직전 기준 측정과 같은 실제 `10i_s1_0844_t080` hand512×512 입력이다.
Peg1,105점(structural1,008 + surface97), Box0점, base0점이다. Base는 같은 hand
depth/calibration을 복제한 빈 mask/관측이므로 **독립적인 두 실제 카메라 관측이나
nonempty Box에 대한 성능 측정은 아니다.** 합성 계약 테스트는 두 카메라·두 물체가
모두 존재하는 경우를 별도로 검사한다.

Packet/관측/view 결과는 실제 GPU 구현으로 timer 밖에서 준비했다. 모든 조합20회
warmup, 각100회 반복, frame/mode 순서를 회전·역순으로 교대했다. 이전 표본의
출력 해제는 다음 표본 timer 밖이다. 시작 전 CUDA 대기는 timer 밖, CUDA endpoint의
종료 동기화는 timer 안이다. CPU wall `perf_counter`로 Python 제어·검사·메모리 할당과
GPU 완료까지 측정했다. Logger/file IO와 최종 FPS/엣지/robot filter/gate는 제외한다.

| Mode | 시작 → 종료 |
| --- | --- |
| `cpu` | 준비된 CPU 관측/structural flags → 기존 CPU 기록·dedup 결과 |
| `gpu` | 준비된 GPU 관측 → GPU 기록·dedup → 동기화 완료 GPU 결과 |
| `gpu_to_cpu` | 위 GPU 경로 + 실제 `numpy_records` → 다음 소비자용 CPU 기록 |
| `legacy_from_gpu` | 같은 GPU 관측 → 기존 `numpy_observations` 반환 → 기존 CPU 기록·dedup |

앞선 CPU-only 기준 측정 EE30.744ms는 CPU 배열이 이미 준비된 시점부터였다.
이번 `cpu` 재측정30.566ms가 이에 대응한다. 두 resident mode의 입력은 각 device에
이미 있으며 업로드/다운로드를 포함하지 않는다. 동일한 GPU 시작·CPU 종료 조건은
`legacy_from_gpu`와 `gpu_to_cpu`를 비교해야 한다.

## 결과

| 좌표계 | Mode | 중앙값 | p95 |
| --- | --- | ---: | ---: |
| EE, 기본 | 기존 CPU `cpu` | 30.565864ms | 34.952199ms |
| EE, 기본 | **GPU 출력 `gpu`** | **4.054146ms** | **4.309229ms** |
| EE, 기본 | GPU + 다음 CPU 소비자용 반환 `gpu_to_cpu` | 5.931168ms | 6.843740ms |
| EE, 기본 | 기존 readback + CPU `legacy_from_gpu` | 31.519443ms | 35.137878ms |
| World | 기존 CPU `cpu` | 28.828715ms | 34.061868ms |
| World | **GPU 출력 `gpu`** | **4.019635ms** | **4.253467ms** |
| World | GPU + 다음 CPU 소비자용 반환 `gpu_to_cpu` | 5.831934ms | 6.662200ms |
| World | 기존 readback + CPU `legacy_from_gpu` | 29.605535ms | 33.747877ms |

EE resident 비교는 약7.54배, 같은 GPU 시작·CPU 종료 비교는 약5.31배다.
GPU/CPU 반환의 중앙값 차이는 독립적으로 잰 순수 전송 시간이 아니다.
CPU 호환 반환에는 readback과 Python dict/배열 복원도 포함된다.
Raw 표본은 제거하지 않았다. World CPU 최대164.179ms, legacy 최대171.485ms인
드문 지연도 보존했다. 원인을 분리하지 않았으므로 GC/공유 host 중 하나로 단정하지
않는다. 이 결과는 동일 입력의 반복 결과이며 전체 pipeline·다양한 장면의 성능은 아니다.

## 정확성·실행 검증

- 최종49개 관련 테스트가 Vast에서 **49개 모두 통과**했다. CUDA 테스트를 실제로
  실행했다. 로컬 macOS는49개 중33개 통과·16개 CUDA skip이며 CUDA를 실행하지 않았다.
- 빈 입력/단일점/2,300점 입력과 permutation, World/EE, 양쪽 물체·camera source,
  structural 우선순위, numeric pixel order, multiple hits와 nontransitive chain을 검사했다.
- Strict3mm/양쪽 nextafter, 음수 cell, 48개 대각선 ULP 경계, NaN인 미관측 특징,
  identity/frame/EE reference, 잘못된 거리/XYZ, 입력 불변성을 검사했다.
- GPU 기록·dedup 호출에서 `.cpu()`, `.numpy()`, `.tolist()`를 금지해도 통과했다.
  기본 Graph test는 CPU view/기록/dedup와 `numpy_observations`를 금지하고 통과했다.
  최종 CPU adapter는 그 이후 별도 단계로 실행한다.
- 실제512 입력은 양 frame 모두 **1,105 → 212개 representative**, duplicates893개,
  source1,105개 보존. 기존 CPU의 모든 기록 field/dtype/value/순서/출처/audit와 정확히
  일치했다. Readback 후의 관측 배열이 변경되지 않은 것도 검사했다.
- 이전 frozen source의 `PlanA`/`CurrentGeometry`를 실제로 별도 로드해, 현재 코드와
  동일 입력의 실제 FK/public Graph 결과를 비교했다. 필터/gate는 준비된 조건으로
  대체했으며 그 알고리즘을 이번 측정에 포함하지 않았다.
- World/EE 모두 최종 **131nodes/1,006edges**. 최종 records·출처와 모든 Graph tensor
  (`node_input`, `node_type`, `edge_index`, `edge_attr`, `edge_type`)가 **정확히 일치**했다.
  모든 tensor의 최대 절대 차이는0이다. 학습/rollout은 실행하지 않았다.
