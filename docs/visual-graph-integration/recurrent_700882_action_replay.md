# 이동 Box 700882의 저장 행동 재생으로 Object21 오차 확인

[최종 앞단을 고정한 Mamba 비교](recurrent_final_gtfree.md)에서 이동 시드 700882의 원본 RGB-D 영상은 저장하지 않았다. 움직임 계획과 Action7은 프레임별로 기록했다. 같은 시드로 시뮬레이터를 초기화하고 원래의 Box 이동 계획과 Action7을 순서대로 적용해 관측을 다시 만들었다. Mamba 모델은 로드하거나 실행하지 않았다. 재생한 RGB-D, 카메라 보정값, TCP는 첫 프레임부터 원래와 같은 검출기, GT 없는 번호 배정, Transformer, 강체 보정, GNN에 전달했다.

## 결과

| 저장한 행동의 출처 | 재생 길이 | 원본 → 재생에서 얕은 진입 오차가 50 mm 이상인 프레임 | 원본과 일치한 프레임 | 재생 종료 |
| --- | ---: | ---: | ---: | --- |
| 기존 Mamba | 242 | 25 → 25 | 25 | 성공 |
| 파인튜닝 Mamba | 250 | 85 → 85 | 85 | 시간 제한 |

두 재생 모두 기록된 GT Peg 중심, GT Hole 중심과 Peg 끝점 상대 위치, Box 이동량이 모든 프레임에서 일치했다. 검출된 슬롯의 물체별 수 역시 모든 프레임에서 일치했다. Object21 횡방향 오차의 원본 대비 최대 차이는 0.00004 mm 미만이었다. 얕은 진입은 GT Peg 끝점이 구멍 단면 안에 있고 입구 면을 0–20 mm 깊이로 지난 프레임이다.

Vast.ai RTX 3090에서 기존 평가의 시뮬레이터 생성 코드와 체크포인트를 재사용했다. 공통 ExperimentLogger로 기록했고 체크포인트, 번호 배정 코드, 원본 롤아웃 해시를 연결했다. 이 실험은 원본 영상의 픽셀 단위 비교 없이 재구성한 관측으로 해당 오류를 재현했다. 앞단 내부에서 누락점 복원과 GNN 중 어느 쪽이 오차를 주도했는지는 분리하지 않았다.

## Expert 궤적과 Peg 슬롯 누락 기간 비교

[앞단 단독 평가](gtfree_frontend_retrain.md)의 Expert 테스트 2,873프레임에서 Peg 직접 검출 슬롯 8개가 모두 비어 있던 경우는 4프레임이었다. 연속 구간은 각각 한 프레임이었고, 얕은 진입 94프레임에서는 한 건도 없었다. 반면 700882의 파인튜닝 후 이동 롤아웃에서는 0부터 세는 66스텝에서 Peg 직접 검출 슬롯이 모두 비었고 249스텝까지 연속으로 유지됐다. 횡방향 오차는 79스텝부터 종료까지 50 mm 이상이었다. 기존 Mamba의 700882 궤적에서도 66스텝 이후에는 Peg 직접 검출 슬롯이 모두 비었다. 수치는 번호가 배정되어 앞단에 전달된 슬롯을 센 것이며, 원시 후보 유무나 미배정 이유는 분리하지 않았다.
