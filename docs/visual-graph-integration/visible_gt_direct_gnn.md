# 가시 GT 꼭짓점을 동결 GNN에 직접 입력한 진단

## 평가 설정

새 Main 카메라에서 가시성이 확인된 Peg, Box 외곽, 앞쪽 Hole 입구의 GT 3D 꼭짓점만 골라 동일한 동결 `VertexEdgeGatedMPNN`에 넣었다. 검출기, Transformer 추적기, TAPNext++, Recurrent, KinFilter는 실행하지 않았다. 기존 Graph 타입을 유지해 Peg는 Peg 노드, Box 외곽과 Hole 입구는 Box 노드로 제공했다. 모든 입력 노드를 현재 관측으로 표시했고 물리 꼭짓점 ID는 전달하지 않았다. TCP 3D 위치, 점 간 거리·상대 좌표와 그래프 연결 방식은 그대로 사용했다.

가시 여부는 기존 팀 함수 `visible_reference`로 정했다. 투영점 주변 7×7 픽셀 안에서 같은 actor의 유효한 Depth 표면이 GT 꼭짓점 6 mm 이내에 있는지를 판단한다. 3D 입력 값은 시뮬레이터 GT 좌표다. 가시성 판정은 물리적 가시성의 래스터 근사다.

카메라는 월드 위치 `[0.65, -0.30, 0.65]` m, 시선 목표 `[0.065, 0.297, 0.11]` m, 수직 시야각 90°, 512×512다. 이전 검출기 평가와 동일한 초기 시드 200–1399 및 scripted expert 16개 시드를 사용했다. 삽입 직전은 삽입 단계에 진입한 15개 에피소드 각각에서 마지막 다섯 파지 유지·정렬 프레임을 뜻한다. GPU는 Vast.ai RTX 3090, CPU PhysX와 CUDA 렌더링·추론으로 실행했다.

### GNN 입력과 출력

GNN은 프레임별 3D 점과 Peg/Box 유형, 현재 관측 플래그, TCP 위치를 사용한다. 출력 순서는 Peg 중심 상대 위치(3), Peg 회전(4), Peg 끝점–Hole 중심 상대 벡터(3), Hole 중심 상대 위치(3), Hole 회전(4), Peg 반크기(3), Hole 반경(1)이다. 중심 위치는 TCP 원점을 기준으로 하고 XYZ 축 방향은 월드와 같다. 상대 벡터의 횡방향 오차는 GT Hole 좌표계의 Y·Z 성분 크기로 계산했다. 끝점 보정 분석은 GNN 내부의 기하 계산값 `endpoint_geom`과 학습 보정값을 더한 최종 예측을 따로 비교한다.

## 결과

1,839개 프레임에서 이전 실험과 seed, step, 단계, GT 21D 및 가시 앞쪽 Hole 점 수가 정확히 일치했다. expert 16개 중 15개가 삽입 단계에 진입했고 875번은 200스텝에서 종료됐다.

### 직접 GT 입력의 오차

각 셀은 **중앙값 / P90**이다.

| 구간 | 프레임 | Peg 중심 (mm) | Peg 축 (°) | Hole 중심 (mm) | Hole 축 (°) | 끝점 횡방향 (mm) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 초기 | 1,200 | 4.52 / 7.18 | 1.64 / 3.30 | 4.01 / 13.00 | 1.15 / 3.98 | 5.09 / 14.90 |
| 첫 파지 | 15 | 80.72 / 153.60 | 12.40 / 66.30 | 13.56 / 25.88 | 1.04 / 3.06 | 13.00 / 137.12 |
| 파지 유지·정렬 | 624 | 5.41 / 108.98 | 1.52 / 10.72 | 6.79 / 25.04 | 1.52 / 5.36 | 8.94 / 30.33 |
| 삽입 직전 | 75 | 5.17 / 13.47 | 1.38 / 5.65 | 12.71 / 32.30 | 4.31 / 8.84 | 15.32 / 31.70 |

첫 파지 15프레임은 GT Peg 가시 꼭짓점 수 중앙값이 4개였다. Peg 중심 오차가 이 구간에서 특히 컸다. 삽입 직전의 가시 꼭짓점 수 중앙값은 Peg 6개, Box 외곽 4개, Hole 앞쪽 림 3개였다. Hole 입구 네 점이 모두 가시한 30프레임만 집계하더라도 Hole 중심 3.80 / 15.26 mm와 횡방향 13.83 / 26.80 mm가 남았다. 서로 다른 프레임 부분집합의 결과이며 가시 점 수 자체의 인과 효과로 해석하지 않는다.

### 삽입 직전 동일 75프레임의 비교

| 조건 | Hole 중심 (mm) | Hole 축 (°) | 끝점 횡방향 (mm) |
| --- | ---: | ---: | ---: |
| 이전 검출기 + Transformer | 4.72 / 23.46 | 1.55 / 6.15 | 6.63 / 17.62 |
| 최신 기본 grid 검출기 + Transformer | 10.88 / 95.50 | 1.89 / 82.04 | 15.47 / 97.61 |
| 이전 검출기의 입구 점만 GT 교체 + Transformer | 4.46 / 8.73 | 1.30 / 3.42 | 6.00 / 11.52 |
| 가시 GT 점 직접 입력 | 12.71 / 32.30 | 4.31 / 8.84 | 15.32 / 31.70 |

가시 GT 직접 입력으로 최신 grid 조건의 큰 오차는 줄었고, 이전 검출·추적 경로보다 남은 오차가 커졌다. 직접 입력은 노이즈를 제거하면서 추적기의 간접 관측 점도 없애고 점의 수·구성과 현재 관측 플래그를 바꾼다. 고정 GNN의 **현재 가시점 입력에서의 자세 복원 한계**를 보여주는 결과이며, GNN 구조의 문제와 가시 정보 부족 또는 학습 입력 분포 차이의 크기는 분리되지 않았다. 최신 RANSAC의 전체 1,839개 비교는 이 평가에 포함하지 않았다.

### Peg 끝점 보정 항

삽입 직전, GNN이 예측한 Peg·Hole 자세와 크기로 계산한 끝점 횡방향 오차는 **15.12 / 31.86 mm**, 학습 보정 후에는 **15.32 / 31.70 mm**였다. 보정 벡터 자체의 횡방향 크기는 **0.31 / 0.64 mm**였다. 이 입력 조건에서는 보정 전부터 오차가 대부분 발생했다.

## 확인 및 산출물

RTX 3090에서 네 구간의 완료 상태, 소스 커밋 `2b6c40e`, 이전과 동일한 GNN SHA-256 및 실제 Main 카메라 투영 설정을 확인했다. 모든 출력이 유한한 21D이고, 상대 벡터 출력이 기하 계산값과 보정값의 합과 일치하는지 검사했다. 기존 모델·공유 환경 코드는 편집하지 않았다.
