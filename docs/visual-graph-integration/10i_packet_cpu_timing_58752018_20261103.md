# Task 10-I — GPU sampling 결과의 CPU 전송·기존 EE 좌표 반환 시간

2026-11-03. 구현 최적화 없이, Shape-First의 GPU 출력 준비 뒤부터 기존 CPU
전송·packet 구성·검증·좌표 변환과 반환까지 측정했다.

## 조건·범위

VastAI **58752018**, AMD EPYC7543, RTX3090. 기존 Python3.12.15,
Torch2.14.1+cu130, Triton3.8.0, NumPy2.5.4 환경을 사용했다.
이전과 같은 실제 `10i_s1_0844_t080` hand-camera **512×512** RGB-D/추론 mask다.
Peg mask61,056 pixels, Box0 pixels, 선택점 **1,105개**다.

GPU sampling은 측정 전에 완료하고 동기화했다. 기본 출력의 **34개 CUDA
tensor**에 기존 출력 device 변환과 같은 `_map_tensors(..., t.to(device='cpu'))`
연산을 적용했다. 각 copy는 blocking CPU 반환이며, 실제 전송·할당·동기화를
포함한다. Tensor leaf별 논리 전송량 합계는 **82,877 bytes(약80.9KiB)**다.
이는 별도 view가 따로 전송되는 양을 합한 값이며 PCIe traffic counter 실측은 아니다.

이어서 runtime helper를 그대로 호출했다:

1. `numpy_selection`: CPU tensor를 NumPy view로 감싼다.
2. `_selection_packet`: 선택점·특징·유효성·source provenance를 camera packet으로 묶는다.
3. `complete_selected_vision_packet`: 기존 검사를 수행하고 점/법선을 camera→EE로
   변환하여 v2 packet을 반환한다.
4. `receive_vision_packet`: 현재 `make_packet`이 반환 전에 수행하는 추가 검증·복사다.

3번까지와4번까지를 각각 독립적인 primary endpoint로 측정했다. 후자는 기존
`make_packet`의 실제 반환 시점이다. 원본 depth/mask/K/pose는 기존 입력 경로처럼
이미 CPU 메모리에 있다. 그 전체 영상이 GPU에서 다시 내려오는 경우를 측정한
것은 아니다. 기록된 실제 camera extrinsic/intrinsic과 TCP pose를 사용했다.

Projection/PCA/Shape-First 자체, sampling 초기화, file IO, World 관측 변환,
카메라 일관성·융합·3mm 중복 제거·최종 cap·Graph 엣지·로봇 필터/gate는 제외한다.

## 측정 결과

Warmup20회 뒤 endpoint별100회를 번갈아 실행했다. 시작 직전 CUDA 동기화는
시계 밖에서 수행해 이전 sampling 대기 시간을 제외했다. CPU copy는 동기적으로
완료되므로 이후 CPU 함수가 반환한 시점에서 끝냈다. NumPy/BLAS/MKL 스레드는1,
CPU affinity와 공유 host 부하는 고정하지 않았다.

| 누적 endpoint | 중앙값 | p95 | 최소–최대 |
| --- | ---: | ---: | ---: |
| **GPU→CPU + 기존 검사·EE 변환·packet 반환** | **2.143ms** | **2.510ms** | 2.049–2.556ms |
| **위 과정 + 수신부 검증·복사 후 기존 함수 반환** | **3.264ms** | **3.740ms** | 3.058–3.947ms |

첫 행은 EE 좌표가 든 packet이 준비된 시점, 둘째 행은 현재 Graph 소비자의
실제 반환 시점이다. 둘째 행은 첫 행을 포함한다. 점 좌표는 `EE_metres`이며
법선도 같은 좌표계로 회전했다. 위 수치를 순수 행렬 곱셈 시간이라고 부르면 안 된다.

별도100회 diagnostic pass에서 단계별 시간을 측정했다:

| 구간 | 중앙값 | p95 |
| --- | ---: | ---: |
| GPU→CPU tensor 전송 | **0.471ms** | 0.520ms |
| NumPy view + camera source packet 구성 | 0.307ms | 0.396ms |
| 기존 검사 + EE 변환 + 반환 packet 구성 | 1.450ms | 1.523ms |
| 수신부 검증·복사 | 1.032ms | 1.083ms |

전송 시간도 단순한 PCIe kernel span이 아니다. 여러 tensor의 copy 호출,
CPU allocation과 동기화가 포함된다. 구간 표본은 별도 pass이므로 중앙값들을
더해 정확한 primary 전체 중앙값을 만들지는 않는다. 전체 시간의 주장은
독립 측정한 누적 endpoint 표를 기준으로 한다. EE 행렬 연산만은 분리하지 않았다.

## 실행 검증

측정 밖에서 실제 public `graph_perception.make_packet(camera, masks)`를 다시
호출하고, 두 endpoint의 **모든 packet 필드**를 재귀적으로 exact 비교했다.
좌표, camera 좌표, EE 변환 행렬, 회전된 특징, validity, source/선택 출처,
schema·dtype·NaN 위치가 모두 일치했다. 검증 좌표와 특징은 NPZ에 보존했다.

Runtime 로직은 수정하지 않았으며 새 benchmark/문서만 추가했다. CUDA 실행은
Vast에서 수행했다. 로컬 macOS에서는 source hash, 원본 통계, syntax와 문서
링크를 확인했고 CUDA timing은 실행하지 않았다. Simulator 생성·rollout·학습/
평가·정책 성공률은 실행하지 않았다. 별도 로봇 필터 작업 파일도 변경하지 않았다.
