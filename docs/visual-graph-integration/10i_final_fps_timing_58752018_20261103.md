# Task 10-I — 기존 물체별 최종128점 FPS 시간

2026-11-03. 기존 NumPy CPU `budget(records,128)`을 그대로 측정했다.
기본 EE 좌표계의 중앙값은 **3.952ms**, p95는 **5.371ms**다.
FPS 구현이나 선택 규칙은 수정하지 않았다.

## 범위·입력

시작은 앞 단계의 GPU3mm dedup 결과가 `numpy_records`로 변환되어 CPU 기록이
준비된 시점이다. 종료는 `budget(records,128)`의 선택된 기록 목록 반환이다.

- 물체별 기록 분리와 좌표계 검사.
- XYZ/persistent ID 배열 준비, stable ID 순서와 첫 점 결정.
- 기본 `hybrid=False`의 일반 NumPy FPS. 이 Peg 입력에서는 첫 점 이후127회
  최소 거리 갱신·최원점 선택·동률 처리.
- 선택한 기록을 원래 관측의 순서/특징/출처와 연결해 목록으로 반환.

GPU→CPU readback 및 Python 기록 변환, 앞선 dedup·view·packet·sampling,
최종 Graph 생성/엣지/Graph 내부의 기록 재정렬, 로봇 필터/gate는 제외한다.
Structural 점을 강제 고정하는 Hybrid FPS를 측정한 것이 아니다.
128점 이하인 물체에는 점을 덧붙이지 않는 기존 short-input 동작도 유지한다.

앞선 측정과 같은 실제 `10i_s1_0844_t080` 손목512×512 입력을 사용했다.
상류 선택1,105점 →3mm dedup 후 **Peg212점 → 최종128점**, **Box0점 →0점**이다.
Base는 hand depth/calibration을 복제한 빈 mask/관측이다. 독립적인 두 실제 카메라나
양쪽 물체가 모두 nonempty인 FPS의 성능은 측정하지 않았다. 512는 상류 이미지의
해상도이고, 이 단계에서 직접 처리하는 좌표는212개다.

## 조건·결과

VastAI **58752018**, AMD EPYC7543. 앞선 CUDA 준비는 RTX3090에서 실행했고,
계측 대상은 CPU다. Python3.12.15, NumPy2.5.4, Torch2.14.1+cu130.
OMP/BLAS/MKL/Torch threads1. CPU affinity·공유 host 부하는 고정하지 않았다.
Python GC는 기본 설정을 유지했다.

EE·World 각각20회 warmup 후100회, frame 순서를 매번 교대했다.
CPU wall `perf_counter`로 직접 합계를 측정했다. GPU 작업은 계측 전에 모두
완료했고, timer 안에는 CUDA 호출·중간 clock·logger·file IO가 없다.
직전 반복의 결과 해제는 다음 timer 밖에서 수행했다.

| 좌표계 | 대상 | 중앙값 | p95 |
| --- | --- | ---: | ---: |
| **EE, 기본** | Peg212→128 + 빈 Box 처리 | **3.952364ms** | **5.371257ms** |
| World | Peg212→128 + 빈 Box 처리 | 3.899309ms | 5.302956ms |

최소/최대는 EE3.875289/5.395318ms, World3.844329/7.348918ms였다.
Raw 표본을 제거하거나 보정하지 않았다. 동일 입력의 반복 결과이며, 과거 다른
입력·실행 경로의 FPS 수치 또는 전체 pipeline 시간과 직접 같은 값으로 해석하지 않는다.

## 실제 실행·정확성 확인

현재 기본 triton_fused `PlanA.represent(..., tensor_records=True)`로 packet/view/
GPU 기록·dedup을 실제 실행하고, `numpy_records`로 CPU 입력을 준비했다.
이 준비와 변환은 전부 timer 밖이다.

현재 로봇 준비 인터페이스에서는 runner에 `robot_filter_backend='cpu'`를 명시하고,
`system.prepare`를 준비된 mask/gate 조건으로 대체했다. 로봇 필터를 실행하거나
수정하지 않기 위한 측정 설정이다. Perception은 여전히 triton_fused이며 GPU에서
동작한다. 실제 FK를 사용한 공개 `CurrentGeometry.build`도 timer 밖에서 실행했다.

- 두 좌표계 모두 선택128점의 **모든 기록 field·배열 dtype/value·순서·출처**가
  공개 `CurrentGeometry.build`의 반환 records와 정확히 일치했다.
- 전체 입력212개 기록의 불변성과 반복 후 동일 선택 결과를 확인했다.
- 각 입력의 persistent ID는 고유하며, 선택 순서를 입력 row index로 저장했다.
- 공개 경로는 각 frame에서131nodes/1,006edges를 구성했다. 이 Graph 시간은 제외했다.
- `core.budget`, `CurrentGeometry`의 imported budget와 NumPy `farthest_rows`가
  같은 실제 함수인지 검사해 native/opt-in patch 경로를 배제했다.
- 로컬에서는 runner 구문·import/CLI를 확인했다. CPU FPS 실측과 상류 CUDA 준비·
  공개 경로 검증은 Vast에서 실행했다. macOS CUDA나 GPU FPS 구현은 실행하지 않았다.
- 이번에는 기준 측정만 했으며 런타임 코드·선택 규칙은 변경하지 않았다.
