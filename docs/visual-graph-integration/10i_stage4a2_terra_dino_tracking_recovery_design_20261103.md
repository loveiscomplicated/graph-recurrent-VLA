# Task 10-I Stage 4A-2: Terra·DINO 초기화 이후 추적 및 복구 비교 설계

**상태: 실행 전 제안.** 기존 고정 시퀀스와 초기 Mask를 재사용해 Terra Standard와 DINO가 SAM2 추적·재탐지 복구에 미치는 차이를 비교한다. 이 문서는 실험 계획이며 결과나 새 실행 승인이 아니다.

## 1. 비교할 질문

1. **지속 추적:** 같은 시퀀스에서 t0 초기화 후 재탐지 없이 SAM2를 계속 실행하면 Terra와 DINO 중 어느 경로가 더 정확한 Mask를 더 오래 유지하는가?
2. **복구와 전체 관측:** 추적이 불확실하거나 초기화되지 않았을 때 재탐지를 허용하면, 두 경로의 시퀀스 전체 품질과 실제 복구 성공·지연은 어떻게 다른가?

첫 질문은 초기화 차이의 영향을 본다. 두 번째는 재탐지 요청부터 응답·적용까지 포함한 운영 경로를 본다. 이 비교에서 DINO는 과거 기준선이며, Terra 채택과 DINO의 향후 모델 설계 제외 결정은 [채택 보고서](10i_stage4a2_terra_standard_adoption_20261103.md)를 따른다.

## 2. 재사용할 자료와 현재 확인 상태

기존 [SAM2 추적 실험](10i_stage4a2_sam2_mask_verifier_tracking.md)은 알려진 8 Parent의 Main/Wrist, 총 16개 시퀀스를 t0~t80의 81프레임으로 평가했다. 총 1,296개 Camera-Frame이며, 과거 DINO+Qwen 초기화 기준 두 물체가 모두 보이는 801개 프레임 중 623개가 Mask IoU≥0.8을 동시에 충족했다. 이 77.8%는 **DINO+Qwen의 기존 결과**로, 이번에 비교할 DINO legacy 선택 규칙의 결과나 Terra 결과가 아니다.

로컬 저장 자료에서 다음을 읽기 전용으로 확인했다.

- 16개 시퀀스의 t0 PNG SHA가 기존 Terra 입력의 t0 PNG SHA와 16/16 일치한다.
- Terra t0 Mask는 **31/32개**가 로컬에 있다. 나머지는 `0844 / Wrist / Fixture`가 GT상 Absent였고 Terra가 null을 반환한 경우다.
- DINO legacy 선택의 t0 Mask도 **31/32개**가 로컬에 있다. 나머지는 `0044 / Wrist / Peg`가 Visible이었으나 DINO가 null을 선택한 경우다.
- 두 시퀀스의 누락 원인이 다르므로, 공통적으로 Mask가 존재하는 대상만 남기는 방식으로 주 결과를 계산하지 않는다. Absent와 Visible 미초기화를 구분한다.
- 기존 [추적 코드](../../graph/experiments/sam2_mask_verifier_tracking_20261102_v1/track.py)는 DINO+Qwen 선택과 그 Mask 목록에 묶여 있다. 저장된 Terra·DINO legacy Mask를 입력으로 받도록 **격리된 실험 경로에서 연결 작업**이 필요하다.
- 시퀀스 Manifest의 JPEG·프레임별 GT 경로는 원격 `/workspace/...`이며 이번 로컬 확인에서는 파일이 존재하지 않았다. 보고서는 원격 보존을 기록하고 있지만 현재 원격 접근성·파일 SHA는 미확인이다. 기존 자료를 찾을 수 있는지 먼저 확인한다. 새 Simulator Render나 Rollout은 이 계획의 기본 단계가 아니다.

원본 시퀀스는 저장된 상태로부터 과거에 복원됐다. 이 실험에서 다시 시뮬레이션 동역학을 실행하거나 실제 Controller의 Closed-loop 동작을 검증한다는 뜻은 아니다.

## 3. 네 조건

| 조건 | t0 초기화 | 추적 도중 재탐지 | 목적 |
| --- | --- | --- | --- |
| A1 | 기존 DINO legacy 선택 → 저장된 SAM2 Mask | 없음 | DINO 초기화 후 유지 기준선 |
| A2 | Terra Standard → 저장된 SAM2 Mask | 없음 | Terra 초기화 후 유지 비교 |
| B1 | 기존 DINO legacy 선택 → 저장된 SAM2 Mask | 공통 규칙에 따라 DINO 재탐지 | DINO 기준 복구 경로 |
| B2 | Terra Standard → 저장된 SAM2 Mask | 공통 규칙에 따라 Terra 재탐지 | Terra 복구 경로 |

모든 조건에서 같은 영상·시점·카메라, SAM2.1 Hiera Small checkpoint, FP32 Weight·BF16 autocast, Mask 임계값·Video Predictor 설정을 사용한다. 각 조건은 독립적인 Tracker State로 실행한다. t0 Mask는 실제 저장된 각 경로의 결과를 사용하며 GT Mask로 교체하거나 실패한 초기를 빼지 않는다. 이전 실험과 마찬가지로 저장 JPEG를 사용한다면 모든 조건에서 같은 JPEG와 동결된 설정을 사용한다.

A1/A2는 16시퀀스씩 32개 Tracker State와 조건별 최대 1,296프레임을 처리한다. B1/B2는 별도 32개 State가 필요하다. 예산·실행 시간은 시작 전 현재 환경에서 산정하며, 재탐지가 없는 비교 결과를 먼저 검토하는 순서를 권장한다.

## 4. A1/A2: 초기화 이후 지속 추적

저장된 t0 Mask를 SAM2 Video Predictor에 넣고 t80까지 전파한다. t0에 Null이거나 Mask가 비어 있으면 그 물체는 미초기화로 남기고, 이후 Visible 구간은 실패에 포함한다. 정상적으로 Absent인 프레임은 해당 물체의 Visible 성공률 분모에서 제외한다.

주 지표는 **두 물체가 모두 Visible인 프레임에서 Peg·Fixture Mask가 모두 IoU≥0.8인 비율**이다. 두 조건에서 같은 GT 프레임·동일 분모를 사용한다. 함께 기록할 지표는 다음과 같다.

- Peg·Fixture별 IoU≥0.8 비율과 평균 IoU, 누락·빈 Mask 비율.
- Wrong-object: 다른 Peg/Fixture/Robot Actor가 예측 Mask Pixel의 50% 이상인 경우. Tiny를 제외한 비어 있지 않은 Mask를 분모로 따로 기재한다.
- 초기화 실패를 포함한 전체 성능과, t0 실제 Video Mask가 성공한 경우에 한정한 이후 유지 성능. 두 번째 수치를 전체 성공률 대신 사용하지 않는다.
- 가장 긴 연속 실패 구간, 시간대별 성공률, Main/Wrist, Parent별 결과. Frame을 독립 Parent로 세지 않는다.

같은 Parent의 두 조건을 대응시키고 Parent별 차이와 Parent-cluster Bootstrap 95% CI를 보고한다. Parent 8개이므로 구간은 넓을 수 있으며 결과를 이 알려진 코호트에 대한 탐색적 관측으로 해석한다.

## 5. B1/B2: 복구와 전체 시퀀스 관측

### 5.1 같은 복구 기회를 만들기 위한 규칙

기존 순수 SAM2 추적 실험에는 재탐지·재초기화가 없다. 다른 Stage4A-2 실험에는 DINO 기반 복구 및 [사후 복구 지연 분석 코드](../../graph/task10i_stage4a2/recovery_event_audit.py)가 있지만, 기존 정책과 DINOv2 기준을 Terra 모델의 채택 경로에 그대로 들여오는 것은 아니다. **평가 지표와 이벤트 기록 방식은 재사용하고, Terra에 적용할 복구 경로는 별도 실험 조건으로 명시한다.**

공정한 비교를 위해 두 경로에 같은 **현재·과거 예측만 이용하는 재탐지 요청 규칙**을 적용할 것을 제안한다. 예를 들어 초기화되지 않은 상태나 예측 Mask의 소실·지속적인 빈 Mask를 감지해 요청한다. 정확한 신호, 연속 프레임 수, 요청 간격, 최대 요청 수와 후보 수용·거부 규칙은 실행 전에 고정해야 한다. GT는 요청을 발생시키는 데 사용하지 않고 평가에만 사용한다.

두 탐지기의 출력이 다르므로 동일한 탐지 점수 임계값이 있다고 가정하지 않는다. DINO의 기존 선택 규칙과 Terra의 JSON/좌표 유효성 검사를 명시하고, 후보를 새 SAM2 입력으로 적용할 때의 공통 검사와 실패 시 처리를 미리 정의한다. Terra가 한 요청에서 두 Box를 반환하더라도 해당 시점에 어떤 물체에 적용했는지 기록한다. 다른 물체나 정상 추적을 잘못 덮어쓰는 부작용도 평가한다.

GT로 확인된 오류의 시작점은 **사후 진단 시각**이다. 이를 실제 재탐지 신호로 몰래 제공하면 실사용 복구 성능이 과대평가될 수 있다. 고정된 시점에 강제로 재탐지하는 보조 실험을 한다면 실용 정책 결과와 별도 진단으로 표기한다.

### 5.2 API 응답 지연을 반영

Terra Standard의 이전 실측 요청 중앙값은 **4.59초**, p95는 **13.67초**였다. 20Hz를 가정하면 t0~t80은 약 4초이므로, 후기 요청은 기존 시퀀스가 끝난 뒤 응답할 수도 있다. 이 경우 응답이 없던 이전 프레임에 미래 결과를 소급 적용해서는 안 된다.

재탐지 요청 프레임, 실제 요청·완료 시각, 당시 이미지와 응답을 적용한 프레임을 기록한다. 결과가 도착하기 전에는 기존 SAM2 추적 또는 미초기화 상태를 유지한다. 응답이 시퀀스 종료 후에 도착하면 해당 시퀀스에서는 **복구 미완료**로 남긴다. 오래된 이미지의 Box를 현재 프레임에 그대로 적용하는 방안은 별도 검증 없이 성공으로 가정하지 않는다.

비교를 돕기 위해 응답 지연을 0으로 취급하는 **이상화된 진단**을 추가할 수 있지만, 실제 시간 반영 결과와 따로 제시한다. 이상화 결과가 항상 상한이라고 가정하지 않는다. 저장 영상 재생은 예측 결과가 미래 시점의 영상이나 GT를 참조하지 않도록 인과 순서를 보장해야 한다.

### 5.3 복구 지표

두 물체 동시 성공률과 물체별 Mask 품질을 A 조건과 같은 기준으로 계산하고, 다음을 추가한다.

- 재탐지 요청·응답·null·실패·적용 수, 요청당 비용과 API 응답 시간.
- Visible한 상태에서 관측이 실패한 구간별 **실제 복구 사건 수**, 복구까지 프레임 수와 실제 경과 시간. 시퀀스가 끝나도 복구되지 않은 사례를 그대로 표기한다.
- 정상 추적 중 잘못된 재초기화로 품질이 나빠진 사건, Wrong-object, 불필요한 요청과 오류를 감지하지 못한 구간.
- A1→B1, A2→B2의 각 경로 내부 변화와 B1↔B2의 경로 간 대응 비교. 복구 지표의 분모와 재탐지 기회 수를 함께 제시한다.

두 물체가 보이는 프레임만 동시 성공의 분모로 사용하고, Absent·Tiny와 미초기화를 별도 기록한다. 복구 가능한 사건 수가 적거나 0이면 강한 복구율 결론을 내리지 않고 사건 수와 사례를 보고한다.

## 6. 비용·보존·진행 순서

1. 지정된 기존 Vast.ai 58576054의 원격 시퀀스·GT·SAM2 checkpoint 존재 및 SHA를 확인한다. 원본 산출물, `PAUSED_SCOPE_REVIEW`, Stop Stub을 보존하고 새 독립 출력 경로를 사용한다.
2. 기존 Terra/DINO 초기 Mask·입력 이미지·설정의 Hash를 고정한다. 로컬의 31개 Terra Mask를 재사용하므로 **A2의 t0 초기화에는 추가 Terra API 호출이 필요 없다.** 원본 31개 DINO Mask도 재사용한다.
3. B1/B2의 요청 규칙·시계·예산·복구 판정과 결과 저장을 **새 A 결과의 GT 채점 전에** 고정한다. 초기 제안은 Terra 재탐지를 **카메라 시퀀스당 최대 1회, 총 최대 16회**로 제한하는 것이다. 응답 실패를 같은 이미지의 자동 Retry로 대체하지 않는다. 이 한도는 사용자가 조정할 수 있는 제안이다.
4. A1/A2를 실행하고 Mask 예측 전체를 동결한 뒤 GT 평가를 수행한다. 기존 Qwen 추적 결과는 보조 참고로만 사용한다. A 결과를 보고 B 규칙을 수정한다면 변경을 기록하고 그 B 결과를 탐색적으로 해석한다.
5. 이전 Terra Standard의 Usage 평균 약 $0.002457/장을 그대로 가정하면 16회는 약 **$0.039**다. 이는 과거 Usage를 사용한 예상치일 뿐 실제 청구액이나 엄격한 비용 상한이 아니다. 실제 토큰 Usage·실제 tier·미확인 요청 예약을 기록하고 GPU 사용료는 별도로 둔다. 새 유료 Instance는 만들지 않고 키는 로컬에 둔다.
6. B 예측·요청 Ledger·시간을 먼저 동결하고 GT로 평가한다. 최종 보고서는 `docs/visual-graph-integration/`에 전체 내용을 저장하며 공통 `ExperimentLogger`를 재사용한다. Production 변경·Graph 생성·학습·Controller 실험·Commit·외부 게시는 범위에 넣지 않는다.

원격 시퀀스가 실제로 없으면 확인된 기존 자료로 가능한 범위를 먼저 보고한다. 새 Simulator Render·Rollout을 자동으로 시작하지 않는다. API 키와 인증 Header는 로그·Manifest에 기록하거나 원격 GPU로 전달하지 않는다.

## 7. 결과를 해석하는 방법

- **A2 > A1:** 이 동일 시퀀스에서 Terra 초기화의 개선이 추적 구간에 얼마나 이어지는지 보여준다. SAM2 자체가 바뀌었다는 뜻은 아니다.
- **B2 > A2:** 제안한 Terra 재탐지 규칙이 실제 응답 지연까지 포함해 관측 유지·복구에 도움이 됐는지 보여준다. 부작용과 미복구 사례도 함께 본다.
- **B2와 B1:** 초기화, 두 탐지기의 출력과 지연, 공통 복구 규칙이 결합된 전체 운영 경로 비교다. 차이를 모델 하나의 순수 효과로 분리하지 않는다.

8 Parent·81프레임의 알려진 저장 시퀀스에서 관측한 결과이며 새 장면 일반화, Graph 품질, Controller 성공률을 이 실험의 결과로 주장하지 않는다.
