# Box 강체 보정을 적용한 Object21 평가

## 실험 설정

[Box 평행 이동 보정](rigid_box_tracking_eval.md)을 기존 RANSAC 꼭짓점 검출기와 Transformer 추적기 뒤에 붙였다. 새 Main 카메라에서 [고정·이동 Box 혼합 GT 학습](moving_box_gt20_training.md)에 사용한 미학습 이동 테스트 시드 32개(3100144–3100175)를 재생했다. Expert 행동으로 생성한 각 프레임에서 두 종류의 그래프를 만들었다.

- **Transformer**는 검출·추적 파이프라인의 기존 좌표를 사용한다.
- **강체 보정**은 추적기가 낸 좌표 중 이전에 관측되었으나 현재 검출이 빠진 Box·Hole 점에 공통 평행 이동을 적용한다. Box 외곽 대응점 세 개 이상이 8 mm 이내에서 합의할 때 이동량을 갱신한다. 관측 갱신이 끊기면 최대 5스텝 속도 외삽을 설정했다. 현재 검출 좌표, Peg 좌표, 점 수, 종류, 관측 플래그는 쌍별로 동일하다.

같은 두 입력을 각각 기존 검출·추적 입력으로 학습한 GNN, 고정 Box의 시뮬레이터 GT 꼭짓점 20개로 학습한 GNN, 고정·이동 Box의 시뮬레이터 GT 꼭짓점 20개를 섞어 새로 학습한 GNN에 제공했다. 모델은 모두 동결했다. GT 입력 수치는 혼합 GNN 및 고정 GT GNN의 같은 프레임 예측을 재사용했다. GT를 추적이나 강체 보정에 제공하지 않았다.

전체 3,352프레임 중 Box가 이동하기 전은 2,077프레임, 실제 이동 중은 695프레임, 이동이 멈춘 뒤는 580프레임이다. 강체 보정은 이 세 구간의 82, 640, 577프레임에서 점 좌표를 바꿨다. 실제 이동 중에는 695/695프레임에서 관측 대응점이 충분해 속도 외삽을 사용하지 않았다. 삽입 직전 집계는 잡기 성공 후 각 궤적의 마지막 정렬 5프레임으로 총 160프레임이고 이 중 157프레임에 좌표 보정이 적용됐다.

## 해석과 범위

이전 실험에서 과거에 실제 Hole 입구 점과 매칭할 수 있었던 미검출 점의 3D 오차 P90은 45.46 → 3.00 mm였다. 그 개선이 Object21 전반으로 이어지지는 않았다. 새 GNN에서 강체 보정은 삽입 직전의 위치 오차를 일부 줄였고 삽입축 오차는 커졌다. 같은 입력에서 기존 검출·추적 학습 GNN의 위치 오차가 더 작았다. 기존 GNN도 이동 중 횡방향 P90은 거의 같았으며 Hole 중심과 삽입축 P90은 개선됐다.

새 GNN은 학습 시 정확한 20점이 모두 관측된 그래프를 받았다. 이번 RGB-D 재생에서 검출과 연관된 track은 프레임당 8–22개였고, 예측 중인 track까지 포함하면 14–39개였다. 강체 보정은 좌표를 수정하며, 현재 검출된 점의 오차, 등록되지 않은 점, 잘못 연결된 track, 점 수나 관측 플래그 차이를 해결하지 않는다. 이 비교만으로 각 입력 차이가 Object21 오차에 얼마나 기여했는지 분리할 수 없다.

평가는 평행 이동하는 Box와 Expert 궤적에서 삽입 단계 진입 직전까지 실행했다. 회전, 실제로 Box 전체가 가려진 구간, Recurrent 제어와 삽입 성공률은 측정 범위 밖이다.

## 검증 및 산출물

Vast.ai의 RTX 3090에서 CPU PhysX, CUDA 렌더링·검출·추적·GNN 추론을 실행했다. 8개 시드씩 네 작업으로 나눴고 작업당 206–238초 소요됐다. 모든 실행을 공통 ExperimentLogger에 기록했다. 네 작업의 완료 상태와 체크포인트 해시, 기존 재생과 GT에 대한 시드·스텝·단계·Box 이동량·강체 이동 추정 일치, 보정 전후 좌표가 같은 프레임의 출력 일치를 확인했다. 시뮬레이터 GT 입력의 기존 횡방향 P90도 다시 계산해 일치함을 확인했다. 공통 런타임 변경 없이 별도 평가 스크립트를 사용했다.
