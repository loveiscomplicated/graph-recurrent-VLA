# 10-I: 엣지 생성·최종 Graph CUDA 전환 — 2026-11-03

기본 `CurrentGeometry(perception_backend='triton_fused')`에서 최종 물체별128점
FPS 결과를 CPU로 내리던 경계를 제거했다. 표면 이웃 탐색, 표면 판정,
free-space 검사, 로봇–물체/Peg–Box 연결, Node21/Edge4 구성과 반환 배열이
CUDA에 남는다. 기존 로봇 필터와 손목 gate 구현은 이번 변경 범위 밖이다.

VastAI **58752018**, RTX3090, **512×512**의 같은 저장 입력으로 측정했다.
EE 기준 Graph 구간 중앙값은 **165.503ms → 6.081ms**, **27.215배**였다.
World 기준은 **145.767ms → 6.069ms**, **24.018배**였다.
이번 실제 표본의 Graph 텐서5개는 EE/World 모두 기존 CPU 결과와 비트 단위로
일치했다. 이 결과는 퍼셉션 전체 시간이나 통합 모델 성공률을 측정한 값이 아니다.

## 구현과 반환 계약

[기본 어댑터](../../graph/plan_a_bc/geometry.py)는 동일 프레임의
`TensorViews`를 한 번 준비해서 `PlanA.represent(..., views=views)`와
`PlanA.graph(..., views=views)`에 공유한다. 역투영·view check에서 준비한
깊이/카메라 보정 텐서를 Graph free-space 검사에서 다시 사용한다.
프레임마다 새 snapshot을 만들며 이전 프레임의 센서 배열을 캐시하지 않는다.

[CUDA Graph](../../graph/persistent_geometry/tensor_graph.py)는 다음을 수행한다.

- 물체0/1, persistent ID 문자열 순서에 맞는 GPU 정렬로 Graph 노드 순서를 유지한다.
- [CUDA KD 구현](../../graph/persistent_geometry/tensor_knn.py)과
  [Triton 커널](../../graph/persistent_geometry/tensor_knn_kernels.py)로 물체별 최대128점의
  이웃을 선택한다. CPU KD-tree 호출이나 점 배열 readback은 없다.
- 기존8-neighbor,20mm 거리, 법선·접선, 세 중간 witness의4mm 지지,
  strict6mm free-space 규칙을 적용한다. 계산은 float64이고 네트워크 입력은
  기존과 같은 float32다. 표면 쌍의 정렬, forward 전체→reverse 전체 순서를 유지한다.
- 로봇 노드별 물체당 nearest4, Peg–Box global nearest16과 기존 거리 동률 순서를
  유지한다. 최종 노드/엣지 타입, 거리·방향 특징도 GPU에서 구성한다.

기본 반환은 `(Graph, TensorRecords, gate)`다. `Graph`의 `node_input`,
`node_type`, `edge_index`, `edge_attr`, `edge_type`과 점별 기록/CSR 출처 배열은
모두 CUDA 텐서다. ID 문자열을 만들기 위해 픽셀 번호를 CPU로 내리지 않도록
`Graph.packet['node_ids_encoded']`에 공통 episode/time/camera-name 메타데이터와
노드 순서의 CUDA `camera_id`/`pixels`를 담는다. `surface_edge_audit`의 값도
CUDA scalar tensor다. Node21/Edge4와 좌표계 label은 바꾸지 않았다.

`numpy_graph(graph)`는 명시적인 CPU Graph/문자열 ID export다.
`numpy_records(records)`는 별도의 기록·전체 출처 export다.
[cache 저장](../../graph/plan_a_bc/cache.py)과
[rollout 진단 파일](../../graph/plan_a_bc/rollout.py)은 파일을 쓰는 위치에서만
이 어댑터를 호출한다. 모델 입력 `pack_graphs`는 CUDA Graph를 직접 받는다.
명시적 `perception_backend='cpu'`의 CPU Graph/Python 기록 반환과 기존 standalone
NumPy/persistent-map 경로는 유지한다. 선택형 `cuda_resident` 실험 경로는
이번 변경의 대상이 아니다.

모든 제어가 GPU 안에만 있는 것은 아니다. Python이 커널을 호출하고 검증·동적
배열 크기에 필요한 scalar를 확인하므로 동기화가 남는다. 작은 episode/pose/
calibration 메타데이터와 세 로봇 FK 좌표의 검증·좌표 준비는 기존 host 규약을
사용하고 CUDA로 올린다. 선택된 물체 점/특징/출처/엣지 배열은 Graph 경로에서
CPU로 반환하지 않는다. 로봇 필터·손목 gate 이전/내부의 CPU 경계까지 없앴다는
의미도 아니다.

## 측정 범위와 시간

측정 endpoint는 **준비된 최종128점 기록 → PlanA.graph → CurrentGeometry._finish**다.
기존 Graph 검증과 current/source/gate 검사도 포함한다. CPU는 NumPy 기록,
GPU는 CUDA 기록에서 시작한다. CUDA 완료 동기화를 타이머 안에 넣어 launch
시간만 재지 않았다. 타이머 시작 전에도 이전 CUDA 작업을 동기화했다.

GPU 기본 행은 앞 단계에서 이미 준비된 `TensorViews`를 사용한다.
별도 `GPU + view 준비` 행은 raw depth/mask/calibration 업로드·깊이 변환과
`TensorViews` 준비도 매번 새로 수행한다. 실제 기본 파이프라인에서는 이 준비를
앞선 view check와 공유하므로 Graph 직전에 다시 하지 않는다.
CPU 기록으로 내리는 전송, 역투영/PCA/Shape-First/dedup/FPS,
SAM2·로봇 필터·손목 gate, 파일 저장·모델 추론은 이 측정에서 제외한다.

| 좌표계 | 구현/범위 | 중앙값 | p95 |
| --- | --- | ---: | ---: |
| EE | 기존 CPU, sparse raw-depth 조회 적용 후 | 165.503ms | 178.471ms |
| EE | GPU, 기존 view 텐서 재사용 | **6.081ms** | **7.208ms** |
| EE | GPU + view 준비/업로드 | 7.471ms | 8.346ms |
| World | 기존 CPU, sparse raw-depth 조회 적용 후 | 145.767ms | 157.422ms |
| World | GPU, 기존 view 텐서 재사용 | **6.069ms** | **7.047ms** |
| World | GPU + view 준비/업로드 | 7.269ms | 8.319ms |

각 행 워밍업20회 후100회를 측정했다. 프레임 순서와 세 mode의 측정 순서를
순환했다. CPU와 GPU 행은 같은 실행에서 비교했다. 별도 프로파일러로 구간을
감싼 시간의 합을 전체 시간으로 사용하지 않았다. Torch/BLAS thread1,
CPU affinity 미고정, 기본 GC를 사용했다. 외부 CUDA 작업이 없음을 시작 전
확인했고 외부 프로세스를 중지하거나 환경 패키지/드라이버를 변경하지 않았다.

직전 별도 실행의 CPU EE167.997ms/World149.931ms와 대체로 같은 범위다.
위 표의 CPU는 **같은 이번 실행에서 재측정한 개선 후 CPU**이며,
전체 깊이 배열을 반복 생성하던 이전793ms 기준과 비교한 배수가 아니다.

## 입력의 한계

입력은 기존 `10i_s1_0844_t080` 저장512 hand-camera 표본이다.
Peg mask61,056픽셀 → Shape-First1,105점 → 3mm dedup212점 → 최종128점이다.
실제512 sensor는 hand_camera 하나이며 base_camera는 depth/calibration을 복제하고
마스크를 비운 입력이다. Box는 비어 있다. 따라서 두 카메라/두 물체가 모두
활성인 실제 입력의 지연시간을 대표하지 않는다. free-space 검사는 이 두
camera 객체를 모두 사용한다. 비어 있는 Box의 Peg–Box 엣지는0개다.

두 물체가 모두 있는 경우는 합성 계약 테스트로 확인했다. 새 GPT Terra 기반
mask, 완전히 보이는 Peg만 추린 학습·평가 데이터, 실제 학습/평가 rollout은
이번에 실행하지 않았다. 속도 개선이 task 성공률 개선을 입증하지 않는다.

## 출력·실행 검증

실제512 표본에서 EE/World 모두 다음 결과를 얻었다.

| 검증 항목 | 결과 |
| --- | --- |
| 노드 | 131 = 로봇3 + Peg128 |
| directed edges | 1,006 = 표면982 + 로봇–물체24 + Peg–Box0 |
| 표면 후보 / 법선 거절 / witness 거절 / free-space 거절 | 584 / 40 / 53 / 0 |
| node_input / node_type / edge_index / edge_attr / edge_type | 기존 CPU 저장 기준과 모두 비트 일치 |
| node_input / edge_attr 최대 절대 오차 | 모두0 |
| 노드 ID/순서, surface audit | 일치 |
| public CurrentGeometry.build | CUDA Graph + CUDA TensorRecords 반환 확인 |
| 기록·전체 병합 출처 | 명시적 export 후 기존 CPU 기록과 일치 |
| CPU Graph builder와 tensor.cpu/numpy/tolist 금지 상태 | GPU Graph endpoint 실행 통과 |

최종 소스로 Vast CUDA 테스트 **74개 모두 통과**했다.
[Graph 테스트](../../graph/persistent_geometry/tests/test_tensor_graph.py)는 빈 입력,
단일 물체/점, Peg·Box 동시 입력, 최대128점씩, feature-invalid NaN 정리,
거리/법선/witness/free-space 경계, EE/World, stale identity/frame,
Wrist Box·rejected Wrist 출처 거절, GPU graph packing과 기존
`DiagnosticEncoder('E0')`의 CUDA 실행을 포함한다.
기존 sparse-depth, geometry, 좌표계, view-consistency 및 robot-overlap 계약도
함께 실행했다. 마지막 검증 후 실행 코드는 변경하지 않았다.

별도 KD 검증225개에서 leaf permutation과 k-neighbor membership이 SciPy
기준과 일치했다. 난수 실수/정수점, 격자, 완전 중복점, 거리 동률,
1~128점의 여러 크기를 포함한다. 최종 커널은 유한 좌표 범위와128점 상한을
검사하고, GPU에서 compact median tree/strict neighbor heap을 사용한다.
목표 정책은 실행한 **SciPy1.18.1/Linux GNU 표준 라이브러리**의 동률 처리다.
다른 CPU 라이브러리/버전의 임의 동률 선택까지 동일하다고 주장하지 않는다.
정책 확인에 사용한 primary source는
[SciPy build.cxx](https://github.com/scipy/scipy/blob/v1.18.1/scipy/spatial/ckdtree/src/build.cxx)와
[query.cxx](https://github.com/scipy/scipy/blob/v1.18.1/scipy/spatial/ckdtree/src/query.cxx)다.

로컬 macOS에서는74개 중58개 통과, CUDA 전용16개 skip이었다.
CUDA 실행 증거는 로컬이 아닌 Vast58752018에서 얻었다.
새 simulator/PhysX 실행과 통합 모델 rollout은 수행하지 않았다.
초기 검증 revision의 실패 로그도 보존했다. v6 benchmark는 측정 후 EE pose의
NumPy float32 JSON export에서 실패했으며 채택한 최종 수치가 없다.
메타데이터를 Python float로 export하도록 수정하고 최종 v8을 새 디렉터리에서
전체 재실행했다. 실패 실행의 결과를 최종 수치에 섞지 않았다.
